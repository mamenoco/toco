# 記事制作アプリ 要件整理

tocoとくらし（toco-to.com）の記事制作を支援するデスクトップアプリの構想メモ。
作りはじめる前に「何を自動化し、何を人がやるか」を決めるための資料。

## 前提（確認済み）

| 項目 | 決定 |
|---|---|
| ゴール地点 | WordPressに**下書き保存**まで。公開は手動 |
| ASP | もしもアフィリエイト（Amazon・楽天・Yahooを一括） |
| 更新ペース | 月10本以上 |
| 操作方法 | 画面のボタンだけで完結（GUI） |
| 対象OS | macOS（Windowsは要確認） |
| 既存環境 | WordPress＋ポチップ（Pochipp） |
| **運営者** | **うさぎと同居。飼育歴1〜3年** |
| **見せ方** | **写真は使わない。自分の言葉（実体験）はテキストで出す** |
| **商品** | **使用中の商品は商品名を出せる。写真は不可** |

---

## 1. 目的の分解

「うさぎの情報サイトでアフィリエイト収益を上げる」を、アプリで動かせる要素まで分解する。

```
収益 = 記事数 × 検索順位 × クリック率 × 成約率 × 報酬単価
```

| 要素 | アプリで改善できるか | 備考 |
|---|---|---|
| 記事数 | ◎ 大きく効く | 手作業だと月10本は現実的に厳しい |
| 検索順位 | ○ | 実体験という一次情報を持つため、内容面では戦える。ドメイン評価は時間が必要 |
| クリック率 | ○ | 商品ブロックの型を揃える、比較表を必ず入れる |
| 成約率 | ○ | 「実際に使っている」記述は成約率に効きやすい |
| 報酬単価 | × | ASPと商材の選択の問題。アプリの管轄外 |

**アプリの役割**：リサーチと執筆の時間を圧縮し、**運営者にしか書けない部分に時間を回すこと**。
記事を量産すること自体が目的ではない。

## 2. 現在の作業フロー分解

今回のケージ記事で実際に行った工程を分解し、担当を割り振る。

| # | 工程 | 内容 | 担当 |
|---|---|---|---|
| 1 | テーマ・キーワード決定 | 「うさぎ ケージ」で書くと決める | **人**（AI補助） |
| 2 | 競合記事の確認 | 上位記事の構成を見る | AI |
| 3 | 商品候補の洗い出し | 楽天で検索、45件から候補を抽出 | **プログラム** |
| 4 | スペック取得 | サイズ・重量・材質・セット内容 | **プログラム** |
| 5 | レビュー収集 | 各商品のレビューを読む | 半自動（※7-1参照） |
| 6 | レビューの傾向分析 | 高評価／低評価の共通点を抽出 | **AI** |
| 7 | 掲載商品の最終決定 | 6点に絞る。価格帯とサイズを散らす | **人** ★ |
| 8 | 記事執筆（調査部分） | スタイルガイドに沿って本文を書く | **AI** |
| 9 | **実体験の記述** | 使っている商品の使用感を書く | **人** ★★ |
| 10 | 事実確認 | 数値・仕様・健康情報の裏取り | **人** ★ |
| 11 | 内部リンク設計 | 関連記事への導線 | プログラム＋人 |
| 12 | WordPress投稿 | 下書き作成、カテゴリ・タグ設定 | **プログラム** |
| 13 | アイキャッチ用意 | 素材サイトかCanvaで作成 | **人** |
| 14 | 公開判断 | 最終チェックして公開 | **人** ★ |

★ = 自動化してはいけない　★★ = このサイトの価値の源泉

## 3. AIが担当すべき領域

### 向いていること

- **大量のレビューから傾向を抽出する**
  クリアケージMのレビュー256件から「ロフトが平ら／滑る／かじる／取り付け位置が極端」という
  共通の不満を拾う作業。人力だと1商品30分かかる。
- **文体の再現**（CLAUDE.mdのスタイルガイドに沿って書く）
- **構成の展開**（「選び方5ポイント」の型にカテゴリ固有の観点を当てはめる）
- **キャッチコピーの生成**

### 任せてはいけないこと

- **事実の断定**（スペック・価格・効果効能）
- **商品の良し悪しの判断**
- **健康・医療に関する判断**
- **実体験の記述** ← AIに書かせると、それは景品表示法上の問題になる（7-2参照）
- **公開してよいかの判断**

## 4. 人が手を動かすべきこと

### 4-1. 掲載商品の最終決定

AIは候補を並べ、レビューを要約するところまで。「この6点を薦める」と決めるのは人。
アフィリエイトは読者にお金を使わせる行為であり、誤った推薦の責任はAIに負わせられない。

### 4-2. 数値と健康情報の裏取り

価格、寸法、重量、成分、獣医学的な記述。アプリが自動取得した値でも、公開前に販売ページで確認する。

### 4-3. 実体験の記述 ← このサイトの核

うさぎと暮らしている運営者が書いていることが、競合との最大の差になる。
写真が使えないぶん、**文章の具体性がすべて**になる。

書き方のルールはCLAUDE.mdの「3. 実体験の入れ方」に定義済み。要点だけ再掲する。

- 入れる場所を4か所に限定する（導入／選び方の各ポイント／持っている商品のブロック／関連アイテム）
- 「観察できた事実」を書く。期間・回数・具体的な出来事が入っていない文は削る
- **持っていない商品に体験を書かない**

飼育歴1〜3年で書ける範囲（お迎え準備、買い替え、失敗した買い物、日々の掃除、換毛期）と、
まだ書けない範囲（高齢期のケア、10年単位の耐久性、複数の病気）を区別する。
書けない領域は調査で補い、体験のふりをしない。

### 4-4. 公開判断

下書きまでで止める設計は妥当。月10本以上を無チェックで公開すると、
誤情報が積み上がったときに巻き戻せなくなる。

## 6. 実体験を扱う設計（このアプリの中核）

写真が使えない以上、実体験はテキストでしか出せない。
そして体験の記述はAIに書かせられない。だからアプリ側は「書く」のではなく「**書く場所を用意し、
書いてはいけない場所を塞ぐ**」役割を持つ。

### 6-1. 持ちもの台帳

| 項目 | 例 |
|---|---|
| 商品名 | 三晃商会 イージーホーム・エボ80 |
| 商品ID | 楽天商品ID / ASIN |
| カテゴリ | ケージ |
| 使用開始 | 2025-04 |
| 使用状況 | 使用中／使用をやめた／買い替えた |
| 気づいたことメモ | 日付つきで追記できる自由記述 |

**気づいたことメモを日常的に貯めるのが、このアプリのいちばん重要な習慣になる。**
「今日、牧草入れの位置を変えたら食べる量が増えた」といったメモが、後から記事の材料になる。
記事を書くときに思い出そうとしても出てこないため、思いついたときに書き足せる導線を作る。

### 6-2. 体験欄の出し分け（ステマ規制をアプリで担保する）

記事に掲載する商品リストと持ちもの台帳を照合し、次のように振る舞う。

| 状態 | アプリの動作 |
|---|---|
| 台帳にある（使用中・使用経験あり） | 体験入力欄を表示。**AIは下書きを書かない**。人が書く |
| 台帳にない | 体験欄を表示しない。AIは「口コミでは〜」の形でのみ記述 |

これにより「使っていない商品に体験を書く」ことが構造的に起きなくなる。
公開前チェックでも、体験段落が台帳外の商品に付いていないかを再判定する。

### 6-3. AIに渡す情報の切り分け

AIには「調査で分かったこと（スペック・口コミの傾向）」と
「運営者が書いた体験メモ」を**別のものとして**渡し、混ぜて創作させない。
体験メモは、文体を整える以上の加筆をさせない。

## 7. 技術構成の案

| 領域 | 案 | 補足 |
|---|---|---|
| アプリ本体 | Tauri（Rust＋Web UI） | macOSのみ。WebViewがアイキャッチ生成にも使える |
| データ保存 | SQLite（ローカル） | 記事・商品・レビュー・持ちもの台帳 |
| 商品情報 | 楽天ウェブサービス 商品検索API | 無料。アプリIDの取得が必要 |
| 記事生成 | Claude API | 従量課金。1記事あたりのコストは要試算 |
| 投稿 | WordPress REST API | アプリケーションパスワードで認証 |
| アフィリリンク | **生成不要** | 下記参照 |

### アフィリエイトリンクについて

ポチップは、もしもアフィリエイトのa_idをWordPress側に一度設定しておけば、
Amazon・楽天・Yahooのリンクを自動でもしも経由に置き換える。

つまり**アプリ側でアフィリエイトリンクを生成する必要はない**。
アプリが出力するのは「どの商品か」を示す識別子（ASIN・楽天商品IDなど）だけでよく、
リンクの生成と価格の更新はポチップ側に任せられる。

- もしもアフィリエイトには公開APIがないため、リンクの自動生成は元々難しい
- ポチップ任せにすれば価格改定にも自動追従できる
- → **本文には価格を直接書かない設計にする**（CLAUDE.mdに反映済み）

**【検証済み・2026-09-01】ポチップはREST API経由で登録できる。**
`wp/v2/types` を確認したところ、`pochipps` がREST有効なカスタム投稿タイプとして登録されており、
`rest_base: pochipps` で GET / POST の両方に対応していた。POSTの引数に `meta` も含まれる。
既に445件の商品データが登録済み（旧記事のぶん）。
→ アプリから商品登録まで自動化できる。半手動の懸念は解消。
　 ただし meta キーの具体的な構造は認証付きで実物を1件取得して確認する必要がある。

### 画像について

写真を使わない方針のため、必要なのはアイキャッチのみ。
月10本ペースだと、これが地味な律速になる。テンプレートを数種類作って使い回す運用を推奨。
商品画像はポチップが自動表示するので、自前で用意する必要はない。

## 8. リスクと制約

### 8-1. レビュー取得の規約リスク ★

今回の記事の質は、レビューの傾向分析に支えられている。しかしここが最も注意が必要な部分。

- 楽天ウェブサービスのAPIでは**レビュー本文は取得できない**（商品情報のみ）
- レビュー本文を機械的に大量取得することは、各サイトの利用規約に抵触する可能性がある
- 高頻度のアクセスはブロックの対象になる

対策の方針：

1. レビュー収集は**自動実行しない**。記事を書くときにボタンを押したときだけ動かす
2. 取得件数と実行間隔に上限を設ける
3. 取得したレビューはローカルに保存し、同じ商品では再取得しない
4. 記事には**本文をそのまま転載せず、傾向の要約として書く**

この方針でもリスクがゼロになるわけではない。運用開始前に各サイトの利用規約を確認すること。

### 8-2. ステルスマーケティング規制（景品表示法）★

2023年10月施行。**使っていない商品を使ったように書くこと**が規制対象になる。
実体験を売りにする以上、ここは最も慎重に扱う必要がある。

→ §6-2の「体験欄の出し分け」で、アプリの構造としてこれを防ぐ。
　 提供品・モニター品を扱う場合は、記事内に明記する運用も決めておく。

### 8-3. 月10本以上のAI記事とGoogleの評価

Googleは「AIで作ったこと」自体を問題視していないが、
「検索順位の操作を主目的とした、価値のない大量生成」はスパムポリシーの対象。

分かれ目は**人による価値の付加があるか**。
実体験を持つことは強い materially な差になるが、
「体験欄が空のまま量産される記事」が増えると意味がなくなる。

→ 公開前チェックに「この記事に一次情報が含まれているか」の判定を入れたい。

### 8-4. 表現規制

うさぎ用品でも、健康・食に関わる商品では効果効能の断定はできない。
CLAUDE.mdの禁止表現ルールをアプリのチェック機能に組み込む。

### 8-5. 価格・仕様の陳腐化

月10本ペースだと1年で120本。→ 本文に価格を書かない設計＋v2で陳腐化チェック。

## 10. サイト現状調査（2026-09-01）

WordPress REST APIから確認した結果。アプリ設計と運用の両方に影響する。

### 良い知らせ

| 項目 | 結果 |
|---|---|
| REST APIの公開 | 有効。`/wp-json/wp/v2/` が応答する |

| 登録済み商品 | 445件（旧記事のぶん） |

### 対応が必要なこと

| # | 内容 | 深刻度 |
|---|---|---|
| 1 | **固定ページが3つしかない**（ranking-top20 / archive / sample-page） | 高 |
| 2 | **プライバシーポリシー・運営者情報・お問い合わせページが存在しない** | 高 |
| 3 | **ヘッダーとフッターの「お問い合わせ」リンクが404**（/contact/ が無い） | 高 |

5については、SEOプラグインを2つ同時に有効化するとmeta要素が重複して出力される。
管理画面でどちらが有効かを確認し、片方に寄せることを推奨。

### 検出したプラグイン

Akismet / All in One SEO / Yoast SEO / WordPress Popular Posts / Google Site Kit / Pochipp

## 11. API費用の試算

実際に書いたケージ記事（8,859文字）の実測をもとに算出。

### 前提

- 日本語は1文字あたり約1トークンとして概算（保守的な見積もり）
- 1記事あたり：入力 約120,000トークン（スタイルガイド＋商品6点ぶんの口コミ＋仕様＋複数回のやり取り）
- 出力 約20,000トークン（記事本文＋中間の分析）

### モデル別の1記事あたり単価

| モデル | 入力 $/MTok | 出力 $/MTok | 1記事あたり |
|---|---|---|---|
| Claude Opus 5 | $5 | $25 | 約 $1.1（約165円） |
| Claude Sonnet 5 | $2 | $10 | 約 $0.44（約66円） |

### 月10本での試算（Opus 5・書き直し2回を見込む）

**約 $22 / 月（3,000〜5,000円程度）**

さらに、スタイルガイドや口コミデータはプロンプトキャッシュに乗せられる。
キャッシュ読み込みは通常入力の約0.1倍の価格なので、書き直しを繰り返すほど実効単価は下がる。
急がない処理はBatch APIに回せば50%になる。

### 結論

**費用は意思決定の制約にならない。** 月数千円の差でモデルを落とすより、
質の高いモデルで書いて手直しを減らすほうが、時間と記事の質の両面で有利。
→ Claude Opus 5 を前提に設計する。

## 12. 旧記事17本の非公開化

### 手順

WordPressの管理画面 → 投稿一覧 → すべて選択 → 一括編集 → ステータスを「下書き」。
17本なので、これはアプリを作らずに管理画面で数分で済む作業。ツール化しない。

### 事前に確認すること

| # | 確認内容 |
|---|---|
| 1 | 固定ページ `ranking-top20` と `archive` が旧記事を参照していないか。参照していればリンク切れになる |
| 2 | トップページの「ピックアップ記事」「コラム」欄が空になる。うさぎ記事を数本入れてから実施するか、先に非公開にするかを決める |
| 3 | `sample-page`（WordPress初期状態）も一緒に削除しておく |

## 13. アイキャッチ自動生成の方針

月10本×12か月=120枚を人手で作るのは続かないため、アプリで生成する。

### 推奨：テンプレート合成（AI画像生成ではなく）

HTMLとCSSでテンプレートを組み、タイトル文字を流し込んでPNGに書き出す方式。

理由：

- **写真がない方針と整合する。** AI生成のうさぎ画像は、実写と誤認される可能性がある。
  実体験を売りにするサイトで、実在しないうさぎの画像を使うのは方向性に反する
- カテゴリごとに配色を変えれば、一覧ページで記事の種類が一目で分かる
- 生成が一瞬で、コストがゼロ。やり直しも自由

### 実装の流れ

1. カテゴリ別のテンプレート（HTML＋CSS）を数種類用意する
2. 記事タイトルと カテゴリ名を差し込む
3. WebViewでレンダリングしてPNGに書き出す（1200×630px）
4. WordPressの `wp/v2/media` にアップロード
5. 投稿の `featured_media` にセット

### 注意点

- **日本語フォントを同梱する。** Noto Sans JP など、再配布可能なライセンスのものを選ぶ
- 長いタイトルの折り返しと文字サイズの自動調整が要る。うさぎ記事のタイトルは40字前後になる
- テンプレートは画面から編集できるようにしておくと、後からデザインを変えられる

### 将来の選択肢

うさぎのシルエットや線画のイラストを1セット用意して差し込むと、写真なしでも見栄えが上がる。
これは外注か素材購入で、一度作れば使い回せる。
